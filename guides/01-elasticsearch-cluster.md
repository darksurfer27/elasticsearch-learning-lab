# 01 — Build a three-node Elasticsearch cluster

[← Preparation](00-before-you-start.md) · [Next: Kibana →](02-kibana.md)

> **Level:** Beginner moving into intermediate. A three-node **secure** cluster requires certificates and careful bootstrapping. This is a guided learning sequence, **not one magic copy-and-paste command**. Do one node at a time.

## Big picture

- A **node** is one machine running Elasticsearch.
- A **cluster** is a group of nodes sharing a `cluster.name` and discovering each other.
- `es01`, `es02`, `es03` have different `node.name` values.
- Elasticsearch's HTTPS API uses **port 9200**; node-to-node communication usually uses **port 9300**.
- **Transport TLS is required for a secure multi-node cluster.** Do not turn off security to avoid certificate errors.

## Step 1 — Install Elasticsearch on Ubuntu (es01, es03)

Run on the Ubuntu servers, one server at a time. Review supported platforms and repository steps if your OS/version differs.

```bash
sudo apt-get update
sudo apt-get install -y curl wget gnupg
wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | sudo gpg --dearmor -o /usr/share/keyrings/elasticsearch-keyring.gpg
echo 'deb [signed-by=/usr/share/keyrings/elasticsearch-keyring.gpg] https://artifacts.elastic.co/packages/9.x/apt stable main' | sudo tee /etc/apt/sources.list.d/elastic-9.x.list
sudo apt-get update
sudo apt-get install elasticsearch
```

**What happened?** You told Ubuntu where the official Elastic package repository is, checked its signing key, then installed Elasticsearch. Save initial credentials and auto-generated security information securely. Do not paste credentials into a README.

## Step 2 — Install on Rocky Linux (es02)

Run on Rocky Linux only:

```bash
sudo rpm --import https://artifacts.elastic.co/GPG-KEY-elasticsearch
sudo tee /etc/yum.repos.d/elasticsearch.repo > /dev/null <<'EOF'
[elasticsearch]
name=Elasticsearch repository for 9.x packages
baseurl=https://artifacts.elastic.co/packages/9.x/yum
gpgcheck=1
gpgkey=https://artifacts.elastic.co/GPG-KEY-elasticsearch
enabled=1
autorefresh=1
type=rpm-md
EOF
sudo dnf install elasticsearch
```

**Check:** `rpm -q elasticsearch` (Rocky) or `dpkg -l elasticsearch` (Ubuntu) identifies the installed package. Keep compatible versions across machines.

## Step 3 — Prepare the Linux kernel

Some Elasticsearch releases require a sufficient `vm.max_map_count`. The example lab used `1048576`:

```bash
echo 'vm.max_map_count=1048576' | sudo tee /etc/sysctl.d/99-elasticsearch.conf
sudo sysctl --system
sysctl vm.max_map_count
```

**Check:** The final command shows `1048576`. Consult Elastic's current requirements for your release.

## Step 4 — Learn the main config settings

Config location on these package installs: `/etc/elasticsearch/elasticsearch.yml`.

```yaml
cluster.name: learning-cluster
node.name: es01
network.host: 192.168.50.11
discovery.seed_hosts: ["es01", "es02", "es03"]
xpack.security.enabled: true
```

**These lines are illustrative, not a complete working secure config.** Copy the matching starter from [`examples/elasticsearch.yml.example`](../examples/elasticsearch.yml.example), edit on each node, and **retain required TLS configuration generated by your chosen security/enrollment process**. On es02, use `node.name: es02`, `network.host: 192.168.50.12`; on es03, use es03 and `.13`.

## Step 5 — Configure secure multi-node transport (IMPORTANT)

This part depends on how you provision certificates. Use Elastic's supported [multi-node security steps](https://www.elastic.co/docs/deploy-manage/security/set-up-basic-security) and [node enrollment documentation](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-with-rpm) before starting extra nodes.

**Option to investigate first:** for a *new* package-based cluster, the current node-enrollment workflow can avoid manually copying private keys. Depending on installation and security state, use `elasticsearch-create-enrollment-token -s node` on the existing node and the documented reconfiguration procedure on new nodes; enrollment tokens expire. Do not attempt to enroll nodes already running with conflicting TLS configs.

If configuring manually:

1. Create trusted transport certificates using `elasticsearch-certutil` and a CA you control.
2. Configure `xpack.security.transport.ssl` on **all** nodes with certificate paths and validation matching their DNS/IP.
3. Set up the HTTP HTTPS certificate/trust (`xpack.security.http.ssl`) on each Elasticsearch endpoint.
4. Restrict private-key access and store passphrases in a keystore rather than plain text where appropriate.
5. Bootstrap the cluster **once** using the current Elastic cluster formation instructions; `cluster.initial_master_nodes` is not a permanent setting. Remove it after the initial cluster formation.

**Why not paste a fabricated TLS config?** Certificate format (`.p12` vs `.pem`), trust roots, passwords, and SAN names change between setups. Guessing those details is more likely to break a real beginner lab than help it.

**Important learning point:** If each node has a different **HTTP CA**, a client trusting only es01's CA cannot automatically connect to es02 and es03. Either share a properly managed CA or configure trust for every selected endpoint.

## Step 6 — Start and verify the services

```bash
sudo systemctl enable elasticsearch
sudo systemctl start elasticsearch
sudo systemctl status elasticsearch --no-pager
sudo journalctl -u elasticsearch -n 60 --no-pager
```

**Check cluster health** from a machine with the correct Elasticsearch HTTP CA and credentials:

```bash
# A 401 response without credentials can prove HTTPS is reachable:
curl --cacert /path/to/http_ca.crt https://192.168.50.11:9200

# Supply the password securely at the prompt; do not type it into command history:
curl --cacert /path/to/http_ca.crt -u elastic 'https://192.168.50.11:9200/_cluster/health?pretty'
curl --cacert /path/to/http_ca.crt -u elastic 'https://192.168.50.11:9200/_cat/nodes?v'
```

**Success looks like:** 3 nodes in `_cat/nodes`, and `"status": "green"` when all expected shards are assigned. A yellow/red state requires investigation; it does not mean "reinstall everything".

## If stuck

See [Troubleshooting](05-troubleshooting.md). Most early problems are **name resolution, firewalls, mismatched versions, TLS trust or bootstrapping order**. Never fix these by deleting Elasticsearch data blindly.
